# 反馈条目模板

```md
### [待处理] <包>: <一句话现象>

- 包/版本：w_tools_<pkg> <x.y.z>
- 环境：<OS / Xcode / Flutter / 设备 / 网络>
- 命令 / 输入：`<可直接复制的命令>`
- 期望：<正常应该怎样>
- 实际：<实际发生了什么，含退出码>
- 影响（我因此做错了什么 / 多花了什么）：<具体后果>
- 建议：<希望怎么改>
- 复现数据：<文件路径 / 输出片段 / 节点 id / 行号>
- 状态变更：<日期> 待处理
```

## 最低可复现标准

- 标题写“现象”，不要写 `x` / `test` / `待定`；
- `命令 / 输入` 必须能复制执行，不要只写 `WImage(...)`；
- `复现数据` 必须是路径 / 代码片段 / 日志，不接受只写 `见附件`；
- `期望` / `实际` 必须描述同一个动作；
- 新条目会自动补 `状态变更：<今天> 待处理`。

## 字段说明

| 字段 | 为什么必须 |
| --- | --- |
| 包/版本 | 13 个包，不写版本无法判断是否已修 |
| 环境 | device / cli / figma 的问题常与 OS、Xcode、网络强相关 |
| 命令 / 输入 | 让维护者不用猜「你怎么触发的」 |
| 复现数据 | 把「不好用」变成「可复现的事实」 |
| 影响 | 决定优先级：多花 20 分钟和多丢一天数据不是一个级别 |
| 状态变更 | 看得出挂了多久，避免「一直待处理」 |
