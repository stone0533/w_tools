## 状态词

| 状态 | 含义 | 约束 |
|---|---|---|
| 已采纳 | 当前有效 | 决策与代码冲突时，要么改代码，要么在新 ADR 里修订 |
| 已取代 | 有更新的 ADR 覆盖 | 顶部必须有 `Superseded by [ADR-000N]` 链接 |
| 已废弃 | 决定不再执行，但没有替代 | 写清废弃日期与原因 |
| 提案中 | 尚未采纳 | 不能被文档当作规则引用 |

## 模板

```md
> 决策记录：记录当时的决策背景；当前实现以模块文档和代码为准。

# ADR 000N：一句话决策

- 状态：已采纳（YYYY-MM-DD）
- 相关：链接到受影响的文档 / ADR

## 背景

当时的问题、证据（数据 / 报错 / 成本）。

## 决策

可执行的规则，按 1 / 2 / 3 编号。

## 后果

正向收益，以及代价 / 已知局限。

## 备选方案

否决了什么、为什么。

## 重新评估的条件

出现什么信号时重新讨论。
```

## 规则

1. 编号四位、唯一、递增；文件名 `NNNN-kebab-title.md`。退役编号不复用，在索引下方注明（由 `scripts/check_docs_facts.py` 检查命名与状态行）。
2. **正文冻结**：旧 ADR 不改决策。补充写新 ADR，并在旧 ADR 顶部加一行指向新 ADR；被完全覆盖时状态改为「已取代」。
3. 不写死当前版本号 / 包数量 / 条目数，统一写「以 `pubspec.yaml` / catalog 为准」。
4. 「决策」里只写类型角色（`Style` / `Options` / `Theme` / 包角色），具体类名放「背景」并标日期 —— 类可能被删，角色不会。
5. 新增 ADR 后同步 [`docs/README.md`](../README.md) 的索引（`check_docs_facts.py` 会拦）。
