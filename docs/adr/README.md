## 状态词

| 状态 | 含义 | 约束 |
|---|---|---|
| 已采纳 | 当前有效 | 决策与代码冲突时，要么改代码，要么追加带日期的「补充」/ 开新 ADR 修订 |
| 已取代 | 有更新的 ADR 覆盖 | 顶部必须有 `Superseded by [ADR-000N]` 链接 |
| 已废弃 | 决定不再执行，但没有替代 | 写清废弃日期与原因 |
| 提案中 | 尚未采纳 | 不能被文档当作规则引用 |

> 状态后可带限定词，例如「已采纳（2026-11-06 补充）」：表示决策主体不变，只追加了带日期的补充。
> 「补充」只增量说明、不改写历史决策；决策被实质改变时开新 ADR（见规则 2）。

## 模板

```md
> 决策记录：记录当时的决策背景；当前实现以模块文档和代码为准。

# ADR 000N：一句话决策

- 状态：已采纳（YYYY-MM-DD）
- 相关：链接到受影响的文档 / ADR

## 背景

当时的问题、证据（数据 / 报错 / 成本）。

## 决策

可执行的规则，按 1 / 2 / 3 编号。

## 后果

正向收益，以及代价 / 已知局限。

## 落地结果

决策落地后回填（新 ADR 写「未执行」）：

- 状态：已完成 / 部分完成 / 未执行
- 证据：版本 / commit / 现行文档
- 与决策的偏差：...

## 备选方案

否决了什么、为什么。

## 重新评估的条件

出现什么信号时重新讨论。
```

## 规则

1. 编号四位、唯一、递增；文件名 `NNNN-kebab-title.md`。退役编号不复用，在索引下方注明（由 `scripts/check_docs_facts.py` 检查命名、状态行与索引一致性）。
2. **正文冻结**：旧 ADR 不改写历史决策。需要补充时：
   - 只做增量说明 → 文末追加 `## 补充（YYYY-MM-DD）`，索引状态写「已采纳（… 补充）」；
   - 决策被实质改变 → 开新 ADR，旧 ADR 顶部加 `Superseded by [ADR-000N]`，状态改「已取代」。
3. 不写死当前版本号 / 包数量 / 条目数，统一写「以 `pubspec.yaml` / catalog 为准」。
4. 「决策」里只写类型角色（`Style` / `Options` / `Theme` / 包角色），具体类名放「背景」并标日期 —— 类可能被删，角色不会。
5. 新增 ADR 后同步 [`docs/README.md`](../README.md) 与本文索引；索引的状态 / 日期必须与正文 `- 状态：` 一致（`check_docs_facts.py` 会拦）。
6. **落地结果要回填**：决策落地后补「状态 / 证据 / 偏差」，不要只留在 commit 历史里；新 ADR 可写「未执行」。
