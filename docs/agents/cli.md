# CLI 使用规则（给人和 AI）

`w_tools_cli` 是消费方项目的接入工具，不依赖 Flutter。

## 先记三步

```bash
dart run w_tools_cli:w_tools init                 # 写入 toolkit / AGENTS / AI_PROMPTS / doctor 配置
# 把 init 打印的 pubspec 片段加入项目，然后 dart pub get
dart run w_tools_cli:w_tools doctor       # 0 error 才算接入完成
```

`init` 默认生成 `.w_tools/AI_PROMPTS.md`（消费者版 AI 任务提示词）；
不需要时用 `--no-ai-prompts`，`--no-instructions` 会一并关闭。

`init` 不会改 `pubspec.yaml`；它保留上次 `.w_tools/init.json` 的 profile/targets/lang，
只有显式参数才覆盖。`--force` 只覆盖文件，不重置参数；要回到默认用 `--reset`。

## 命令选择

| 场景 | 命令 |
| --- | --- |
| 第一次接入 / 升级后刷新 | `init`；有 drift 时按输出用 `init --force` |
| CI 检查接入约定 | `doctor --format=json`（warning 也失败加 `--strict`） |
| 给 AI 项目事实 | `context --format=prompt` |
| 找组件 | `list <关键词>`；给 AI 加 `--format=prompt` |
| 看组件怎么用 | `explain <组件名>`；给 AI 加 `--format=prompt` |
| 记录 w_tools 问题 | `feedback search` 查重 → `feedback submit --package=<包>` |

所有命令：`dart run w_tools_cli:<command> --help`。

## AI 闭环

```bash
dart run w_tools_cli:w_tools context --format=prompt   # 1. 项目事实
dart run w_tools_cli:w_tools list 表单                  # 2. 找组件
dart run w_tools_cli:w_tools explain WFormDropdown     # 3. 用法/反例/import
dart run w_tools_cli:w_tools doctor --format=json  # 4. 写完自检

# 被 w_tools 卡住 / 有改进建议（默认关闭，先看 feedback.issue）：
dart run w_tools_cli:w_tools feedback search "关键词" --package=<包>
dart run w_tools_cli:w_tools feedback submit --template > /tmp/feedback.md   # 可选：打印骨架
dart run w_tools_cli:w_tools feedback submit --package=<包> --title="<现象>" --body-file=/tmp/feedback.md
```

## 关键边界

- `explain` 在已 init 的项目里输出**聚合入口** import；子包 import 只允许出现在
  `lib/app/ui/`、`lib/app/design_system/` 与 toolkit 自身（R2 例外）。
- `doctor` 的 R2 会把业务代码直接 import `package:w_tools_*` 判 error；不要照抄组件目录里的子包 import。
- `rules:` 里 `R2: false` 这类开关对全部规则生效；`--only=R1,R2` 是本次运行的白名单。
- `list` / `explain` 没找到时退出码 1；参数错误 2。
- `feedback path` 在消费方默认只提示未启用，不返回本地收件箱路径。
- `feedback` 是记录 **w_tools 本身**的问题，不是业务代码问题。
- **在 w_tools 仓库检出内**：默认直接追加 `docs/feedback/<包>.md` 并更新索引（`--ledger`）。
- **消费方**：默认**不提交**；只有 `.w_tools_doctor.yaml` 的 `feedback.issue: true` 时才建 Issue
  （需已安装 gh；gh 读取 `GH_TOKEN`/`GITHUB_TOKEN` 或登录态）。两者都不满足 → 什么都不做。`--issue` 可一次性覆盖。
- 生成物头部有 `generated by w_tools_cli x.y.z`；升级后先 `init --check-drift`。

## 常见错误

| 现象 | 原因 / 处理 |
| --- | --- |
| init 后 doctor 全红 R7 | pubspec 依赖还没加；按 init 输出的片段补齐并 `pub get` |
| `explain` 的 import 被 R2 判红 | 业务代码改用聚合入口；需要子包 import 时确认文件在白名单 |
| `init --check` 一直失败 | 文件缺失或 drift；按输出运行 `init` / `init --force` |
| toast 全部静默 | 没挂 `BotToastInit()` / `BotToastNavigatorObserver()`；见 [toast.md](toast.md) |
| 反馈没有提交 | 默认关闭：仓库内用 `--ledger`；消费方开启 `feedback.issue: true` 后 `--issue`；否则跳过 |
| 不确定当前通道 | `dart run w_tools_cli:w_tools feedback status --json` |
| 不想保留上次选择 | `init --reset` |
