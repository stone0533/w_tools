# CLI 使用规则（给人和 AI）

`w_tools_cli` 是消费方项目的接入工具，不依赖 Flutter。

## 先记三步

```bash
dart run w_tools_cli:w_tools init                 # 写入 toolkit / AGENTS / AI_PROMPTS / doctor 配置
# 把 init 打印的 pubspec 片段加入项目，然后 dart pub get
dart run w_tools_cli:w_tools doctor       # 0 error 才算接入完成
```

`init` 默认生成 `.w_tools/AI_PROMPTS.md`（消费方场景提示词库）；
不需要时用 `--no-ai-prompts`，`--no-instructions` 会一并关闭。

`AI_PROMPTS.md` 给**使用 w_tools 的开发者**（Dart / Flutter 开发者、对写提示词不熟）用，不是给 agent 的规则书：
场景编号是「族字母-工序号」（`A-1` 计划 → `A-2` 实现、`E-1` 审计 → `E-2` 修复、
`F-1`→`F-2`→`F-3` 升级），贴一段做一件事。规则主体仍在项目规则文件（`AGENTS.md` / `CLAUDE.md` / …），两者别互相扩写。

生成时会按本次 targets、`toolkit_entry` 与 pubspec（Flutter / 纯 Dart、聚合包 / 子包）渲染固定前缀，不写死 `AGENTS.md` 或 `flutter` 命令。

`init` 写进项目的指令片段固定四段：`怎么用 w_tools`（context → list / explain → 聚合入口）、
`硬规则`（R1 / R2 及 import 例外 / 生成物 / 暂存层 / R9）、`组件约定`（每个启用的包一行：主入口 + 一句话规则 + `explain` 入口）、
`完成前`（doctor → analyze / test → 反馈开关）。片段只做**路由**：组件用法与反例以 `explain` 为准，
分支流程（Figma / 设备 / 反馈 / 场景）在 `AI_PROMPTS.md` 或工具 README。
片段在 `w_tools:begin/end` 标记块内（`init` 会刷新，块内手改会先备份），块外的 `## 项目规则` 归项目自己。

它是生成物：内容与模板不同时 `init` 不覆盖、只报 drift；`init --force` 直接覆盖且**没有备份**，
项目自己的提示词请另存。

升级到 1.10+ 后，已有项目首次 `init --check` 会因缺少 `.w_tools/AI_PROMPTS.md` 报缺失；
运行一次 `init` 补上，或用 `init --no-ai-prompts` 关闭。`--no-instructions` 与 `--ai-prompts`
不能同时显式使用。

`init` 不会改 `pubspec.yaml`；它保留上次 `.w_tools/init.json` 的 profile/targets/lang，
只有显式参数才覆盖。`--force` 只覆盖文件，不重置参数，也不覆盖 `.w_tools_doctor.yaml`；
要覆盖项目配置用 `--force-config`（先 `.bak`），要回到默认 profile 用 `--reset`。

## 命令选择

| 场景 | 命令 |
| --- | --- |
| 第一次接入 / 升级后刷新 | `init`；有 drift 时按输出用 `init --force` |
| 恢复默认 doctor 配置 | `init --force-config`（先写 `.bak`） |
| CI 检查接入约定 | `doctor --format=json`（warning 也失败加 `--strict`） |
| 给 AI 项目事实 | `context --format=prompt` |
| 找组件 | `list <关键词>` 或 `list --package=<包>`；给 AI 加 `--format=prompt` |
| 看组件怎么用 | `explain <组件名>`；给 AI 加 `--format=prompt` |
| 记录 w_tools 问题 | `feedback search` 查重 → `feedback submit --package=<包>`；默认路由：本地台账 → Issue → 跳过（exit 4）；ledger 默认拒绝重复，确认重复加 `--allow-duplicate` |

所有命令统一走 dispatcher：`dart run w_tools_cli:w_tools <command> --help`
（`w_tools_cli:init` 这类兼容入口仍保留，但新文档统一写 dispatcher 形式）。

## AI 闭环

人先按 `.w_tools/AI_PROMPTS.md` 选场景（`A-1` / `B-1` …，记反馈是 `L-1`）并填空，贴给 AI；AI 侧再走：

```bash
dart run w_tools_cli:w_tools context --format=prompt   # 1. 项目事实
dart run w_tools_cli:w_tools list 表单                  # 2. 找组件
dart run w_tools_cli:w_tools explain WFormDropdown     # 3. 用法/反例/import
dart run w_tools_cli:w_tools doctor --format=json  # 4. 写完自检

# 被 w_tools 卡住 / 有改进建议（默认关闭，先看 feedback.enabled）：
dart run w_tools_cli:w_tools feedback status --json                  # 通道：ledger / issue / disabled
dart run w_tools_cli:w_tools feedback search "关键词" --package=<包>
dart run w_tools_cli:w_tools feedback submit --template > /tmp/feedback.md   # 可选：打印骨架
dart run w_tools_cli:w_tools feedback submit --package=<包> --title="<现象>" --body-file=/tmp/feedback.md
```

## 关键边界

- `explain` 在已 init 的项目里输出**聚合入口** import；子包 import 只允许出现在
  `lib/app/ui/`、`lib/app/design_system/` 与 toolkit 自身（R2 例外）。
- `explain` 会读 `pubspec.lock` 标注 `包版本`，并给出该版本对应的 pub.dev `API 文档`；
  仓库 `main` 文档链接可能领先于已安装版本，以 `包版本` 为准。
- 在 w_tools 仓库检出内，`context` 会标记“仓库检出”并跳过消费方 doctor；
  消费方项目才跑 R1~R9。
- `doctor` 的 R2 会把业务代码直接 import `package:w_tools_*` 判 error；不要照抄组件目录里的子包 import。
- `rules:` 里 `R2: false` 这类开关对全部规则生效；`--only=R1,R2` 是本次运行的白名单。
- `list` / `explain` / `feedback search` 没找到时退出码 1；参数或配置错误 2；gh 等外部工具不可用 3；
  `feedback submit` 没有可用通道时 **4**（什么都没写）。
- `feedback path` 只返回**真实可写**的台账路径（仓库自身或本机 w_tools 检出）；两者都没有时明确提示未启用，
  不返回旧的本地收件箱。
- `feedback search --gh` 在 `gh` 未安装 / 未登录时退出 `3`，且不返回本地结果；
  只想查本地台账时去掉 `--gh`。
- `feedback` 是记录 **w_tools 本身**的问题，不是业务代码问题。
- **通道只有一套判定**（`submit` / `status` / `path` / `search` / `lint` 共用）：
  1. 项目根是 w_tools 仓库 → 写该仓库 `docs/feedback/` 并更新索引（维护者默认，不读开关）；
  2. `feedback.enabled: true` 且本机解析到 w_tools 仓库检出（path / git 依赖）→ 写**那个仓库**的台账，
     **不建 Issue**（本地优先）；
  3. `feedback.enabled: true` 但本机没有检出 → 建 GitHub Issue（需已安装 gh；gh 读取
     `GH_TOKEN`/`GITHUB_TOKEN` 或登录态）；
  4. 其余 → 跳过：不写文件、不建 Issue，`submit` **exit 4**（AI / CI 不能当成功）。
- `feedback.enabled` 默认 `false`；旧键 `feedback.issue` 仍兼容（`enabled` 优先）。
- 仓库 clone 在别处（依赖解析不到）时用 `feedback.ledger: <路径>` 显式指过去；指向的不是
  w_tools 仓库会在 stderr 提示一次并忽略，不会静默写错地方。
- `feedback.max_issues_per_day`（默认 5，0 = 不限）只约束**公开 Issue**：CLI 没有会话概念，
  用日额度兜住「一次会话 3–5 条」；额度耗尽 exit 2，本地台账不占额度。计数在
  `.w_tools/feedback_budget.json`（删了即归零，跨天自动重置）。
- 从消费方写本机 w_tools 检出时会在 stderr 提醒「工作区会变脏」，提交前要 commit / discard。
- **开关是硬门禁**：未开启时 `--issue` 不绕过（exit 2）；本机有台账时 `--issue` 才是「明确要公开提 issue」的覆盖。
- 本机没有台账时 `search` 查不到东西，会提示加 `--gh` 搜 GitHub issues。
- pub cache 里的 git 依赖（`~/.pub-cache/git/…`）不算「本机库」：不往缓存写台账，按「没有本地仓库」处理。
- 生成物头部有 `generated by w_tools_cli x.y.z`；升级后先 `init --check-drift`。

## 常见错误

| 现象 | 原因 / 处理 |
| --- | --- |
| init 后 doctor 全红 R7 | pubspec 依赖还没加；按 init 输出的片段补齐并 `pub get` |
| `explain` 的 import 被 R2 判红 | 业务代码改用聚合入口；需要子包 import 时确认文件在白名单 |
| `init --check` 一直失败 | 文件缺失或 drift；按输出运行 `init` / `init --force` |
| toast 全部静默 | 没挂 `BotToastInit()` / `BotToastNavigatorObserver()`；见 [toast.md](toast.md) |
| 反馈没有提交（exit 4） | 默认关闭：仓库内用 `--ledger`；消费方在 `.w_tools_doctor.yaml` 开 `feedback.enabled: true`；未开启时 `--issue` 也会 exit 2 |
| 不确定当前通道 | `dart run w_tools_cli:w_tools feedback status --json` |
| 不想保留上次选择 | `init --reset` |
